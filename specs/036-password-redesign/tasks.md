**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/references.md](./contracts/references.md), [contracts/passkey-service.md](./contracts/passkey-service.md), [contracts/tauri-commands.md](./contracts/tauri-commands.md), [quickstart.md](./quickstart.md)

**Tests**: Included. The constitution requires an executable check for non-trivial logic: Rust unit tests in sibling `*_tests.rs` files, Rust integration tests in `src-tauri/tests/`, pure TypeScript checks `scripts/check-passwords-*.ts` (already run by `pnpm check:passwords` through its glob, no new CI wiring), and end-to-end scenarios. Tests come first inside each story and fail before the code exists. Swipe and lightbox gestures, native file dialogs and the system clipboard seen from other programs are manual (quickstart M1, M3, M6): the e2e rig has no reliable touch gestures (research R17).

**Organization**: Grouped by user story, in the five delivery stages of the plan (each stage is one PR and ships on its own): Stage 1 = Phases 3–4 (US1, US2), Stage 2 = Phases 5–6 (US3 without copy, US4), Stage 3 = Phases 7–8 (US7, then US3's copy dialog), Stage 4 = Phase 9 (US5), Stage 5 = Phase 10 (US6). Priorities: P1 US1, US2, US3; P2 US4, US5, US7; P3 US6. The branch `036-password-redesign` starts from `main` after PRs #228, #229 and #234.

**Shipping note**: Stage 1 and 2 need no Rust. Migration `0024` (shipped as `0026`, spec 017 took `0024` and `0025`) lands once, in Stage 4 (the passkey-links table); Stage 3 uses no new table. The copy dialog (Stage 3) shows "Passkeys per Verweis" only after Stage 4 (flag `passkeyLinksAvailable`, T065), and the command rejects the option before then. If a stage needs a second PR for review fixes, that is fine; do not mix stages.
