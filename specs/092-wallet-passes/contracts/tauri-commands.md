# Contract: Tauri commands for passes (user interface)

The user interface calls the backend only through these commands (034: no SQL in the frontend). They live in
`src-tauri/src/passwords/commands/pass.rs`, delegate to `service/pass.rs` with `Caller::User`, and are registered next to the
other `passwords_*` commands in `src-tauri/src/lib.rs`. Types are generated by ts-rs into `src/types/bindings/`. All
arguments are one object, as in `usePasswords.ts`. Errors use the existing `errors.passwords.*` codes plus the ones named here.

**Rule for every command here:** a code value is returned only by `passwords_pass_codes` and `passwords_pass_code_svg`
(one entry, the user's own screen), by `passwords_history_reveal` on request, and by `passwords_pass_codes_scan` as the result of
a scan the user started. It is never in a header, a list, an event, a log line, an error text or a tab location (FR-025).

## New commands

### `passwords_pass_create`

`{ input: PassInput, groupId?: string | null }` returns `ItemDetail`.

`PassInput`: `title?`, `note?`, `url?`, `icon?`, `color?`, `expiresAt?` (date), `passKind`, `start?` (`{ date }` or
`{ at, zone }`), `parentId?`, `codes: [{ id?, format, value, label?, position }]`, `keyValues`, `tagNames`. One transaction (R13).
Errors: `pass.code_invalid` (`{ position, reason }`, a hand-typed code that does not fit its format) and `pass.parent_loop`.
A parent that is not in the vault (not yet synced) is allowed: the link is soft.

### `passwords_pass_update`

`{ id, updatedAt, patch: PassPatch }` returns `ItemDetail`. Same conflict token as `passwords_update_item`
(`PasswordsConflict { changed | deleted }`). `PassPatch` carries any subset of the `PassInput` fields; `codes`, when present, is
the whole list **by code id**: a code that carries an id keeps its row (and its id) with the new values, a code without an id is a
new row, and a stored row whose id is missing from the list is deleted. Rows are never deleted and re-inserted with new ids, so two
replicas that edit different codes of one pass merge row by row (CRDT) and do not end with two sets; two replicas that both add
the same new code each add a row, and the user removes the duplicate. Refuses a change of kind. Errors as above.

### `passwords_pass_codes`

`{ id }` returns `[{ id, format, label, position, flag, value }]` for one pass, ordered by position. The only bulk read of
values; one entry per call. Refused for an entry that is not a pass or is in another caller's scope.

### `passwords_pass_code_svg`

`{ id, codeId }` returns `{ svg, width, height, quietZone }`: the drawing of one code, dark on white, with the quiet zone of its
format (FR-009). Computed in Rust from the stored value; no network. A code flagged `invalid_value` or `unknown_format` returns
`{ svg: null, text }` so the view shows the text (FR-003).

### `passwords_pass_code_check`

`{ format, value }` returns `{ ok: true } | { ok: false, reason }`: the check the editor runs while typing (one rule, R3).

### `passwords_pass_set_parent`

`{ id, updatedAt, parentId: string | null }` returns `ItemDetail`. Sets or clears the link. Errors: `pass.parent_loop` (the new
parent is the pass or one of its descendants), `pass.not_a_pass`.

### `passwords_pass_place_proposal`

`{ passKind, hasDate, provider? }` returns `{ folderPath: string[] | null, tagName: string | null }`: the rule of FR-019, used by
the import and capture dialogs. Pure; creates nothing. The dialog creates the folder and tag when the user confirms, reusing an
existing one of the same name (case ignored).

### `passwords_pass_import_preview`

`{ file: PickedFile, language?: string, checkSignature: boolean }` returns `PassImportPreview` (`language` is the language of the window; `checkSignature` ships with the signature task):

```text
{ previewId, pass: { passKind, title, provider, start?, expiresAt?, codes: [{ format, label, flag? }], fields: [{ name, value }],
  hasIcon }, proposal: { folderPath, tagName },
  duplicateOf?: { id, title }, signature?: { state: "valid"|"invalid"|"not_checkable", issuer?, reason? },
  notKept: [{ what, why }] }
```

`PickedFile` is a path or a `content://` URI (spec 043). The file is read with the limits of research R6, kept only in memory
or in a folder of the vault folder named for its purpose (spec 084 FR-002), and never sent anywhere. `codes` here carries format and label, not a value.
Errors: `pass.not_a_pass_file` (refused with the reason, nothing left behind, FR-033). Several files: the dialog calls this
once per file; one failing does not stop the others.

### `passwords_pass_import_save`

`{ previewId, choices: { title?, passKind?, start?, folderPath: string[], tagName?, parentId?, onDuplicate: "ask"|"skip"|"add" } }`
returns `{ id?, report: PassImportReport }` (`id` is absent when a duplicate is skipped; `ask` with a duplicate is refused with `pass.duplicate` and the existing id) (a new type for one pass: the existing `ImportReport` only holds counters). Writes through the same transaction as `passwords_pass_create` and removes the
temporary file. The report names the entry, the place and what was not kept, and holds no code or secret (FR-032).
`passwords_pass_import_cancel { previewId }` removes the temporary file.

### `passwords_pass_codes_scan`

`{ image: bytes }` (a photo, or one rendered PDF page as PNG) returns `[{ format, value }]`: every code found. The caller
shows them, the user picks, and the values go into `passwords_pass_create` or `passwords_pass_update`. Nothing is saved by this
command. Live camera frames use the existing camera commands (spec 085) with the `rxing` reader (research R15).

### `passwords_pass_links`

Not a command: the "Belongs to" state and the "Linked" list are computed in the client from the headers (research R8), so a
change by sync shows at once.

## Events

None new. `vault-data-changed` already names `haex_passwords_pass_details` and `haex_passwords_pass_barcodes` (research R12);
the store reloads quietly and an open editor keeps its draft (034 FR-038).

## Route contract (frontend)

| Place                            | Query keys allowed                                                | Note                                                   |
| -------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------ |
| `entry/new`                      | `type=pass` (new), `parent=<id>` (new, "Add linked pass"), `edit` | `type` accepts only `pass`; `parent` is an opaque id.  |
| `entry/:id`, `entry/:id/history` | `edit`, `tab`                                                     | as 034.                                                |
| `''`, `folder/:id`               | `q`, `tag`                                                        | as 034; sort and filter are in a store, not the route. |

`registry.ts` `isSecretFreeLocation` and `scripts/check-passwords-routes.ts` are extended for the two new keys; titles stay
static (`wm.passwords.*`).
