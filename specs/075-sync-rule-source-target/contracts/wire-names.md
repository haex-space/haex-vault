# Contract: names on the wire

Everything the frontend, an agent or a generated file sees. No alias for the old names.

## Tauri commands and events

The command names do not change (`sync_rules_*`). Their payloads and results change by the field renames of
[data-model.md](../data-model.md): `SyncRuleDraft`, `SyncRule` and the views that embed them carry `source` and
`target` (each `{ location, path }`) instead of `placeA` and `placeB`; direction is `sourceToTarget` or `both`; a
side in `SyncRulePending`, `SyncRulePlanStep` and `SyncRuleRunItem` is `source` or `target`. Events carry the same types.

`specs/061-sync-rules/contracts/tauri-commands.md` is updated to match (FR-008).

## Generated bindings (`src/types/bindings/`)

Regenerated by `cargo test`, then trailing blanks stripped by the CI's `sed`. Five files change:

```ts
export type SyncRulePlace = { location: SourceRef; path: string }
export type SyncRuleSide = 'source' | 'target'
export type SyncRuleDirection = 'sourceToTarget' | 'both'
// SyncRule and SyncRuleDraft: `source: SyncRulePlace, target: SyncRulePlace`
// SyncRulePending, SyncRulePlanStep, SyncRuleRunItem: `side: SyncRuleSide` (the type carries the change)
```

## Agent tools (`src/lib/actions/syncRuleActions.ts`)

The `DRAFT` schema, used by create and update, and the `VIEW` schema:

```ts
properties: {
  name: …,
  source: { ...PLACE, description: 'The source. Its .haex-ignore file holds the exclusions of the rule.' },
  target: { ...PLACE, description: 'The target.' },
  direction: { type: 'string', enum: ['sourceToTarget', 'both'],
    description: 'sourceToTarget: one way from the source to the target; both: both ways.' },
  …
}
required: ['name', 'source', 'target', 'direction', 'deleteMode', 'intervalSecs', 'enabled', 'allowDecrypted']
```

`PLACE` becomes `{ location: <the source reference>, path: string }`, `required: ['location', 'path']`.

- A call that sends `placeA` or `placeB` is refused: the draft is complete, `source` and `target` are required, and
  `serde_json::from_value::<SyncRuleDraft>` reports the missing field as an invalid-input error. No rule changes.
- The view an agent reads back uses the same names.
